\section{Related work}

Research around this topic is focused on maze generation as well as tree search and maze solving solutions. 

\cite{vijayaAnalysisMazeGeneration2024} Vijaya et al discussed the use if mazes within game design. going into how different algorithms can lead to a sense of predictablility and therefore boredom when playing. this particular paper explores depth first search, in both solving the maze as well as generating one - both in the form of recursive backtracking algorithms. It concludes that the depth-first search algorithm is an excellent joice for maze generation as it seems to have a brilliant comprimise between playability, challenge for the solver with path lengths averaging 122\% of the max path length\cite{vijayaAnalysisMazeGeneration2024} as well as computational efficiency.

\cite{narendranMazeSolverExploringAlgorithmic2024} Narendran et al explore the effectiveness of various path finding algorithms within a maze. The authors compare fairly basic Breadth-first search, as well as depth-first search with A* search 2 variations aof Markov Decision Process as well as a Enhanced wall follower. The paper goes into depth of how many steps taken, memory usage and time complexity of these algorithhms. This study is particularly relevant as it is very similar to mine. I am differentiating through comparing the first 3 algorithms and last within mazes generated by different algorithms, as well as this these mazes, unlike this work, will not contain loops.

\cite{MazeAlgorithms} James Buck Goes into varying detail about 15 different algorithms to generate mazes. ranging from the fairly standard recursive backtracker, to the wildly inefficient Aldous-Broder algorithm. This blog and his subsequent book \cite{buckMazesProgrammersCode2015a} which goes into more detail about how to implement said algorithms and how they work, whilst also discussing how to add braiding, weaves and different grids.

\cite{zotero-item-159} Prim explores what would be known as prim's algorithm, using this method to generate minimum spanning trees between points. This manuscript references the earlier paper by Kruskal\cite{kruskalSHORTESTSPANNINGSUBTREE} comparing his solution with kruskals, and discussing the possibilities against various problem including the traveling salesman problem. 

\cite{kozlovaExaminationRepresentationalExpression2015} Kozklova et al, compare 3 maze generation algorithms: prims, depth first and recursive Division. This summises that depth first would be the best of the 3 due to the long path ways agains Prim's short, but also relatively wiggly passages compared to the recursive division.

\cite{veritasiumFastestMazeSolvingCompetition2023} Derek Muller, Veritasium, did a video exploring the popular micro mouse compition. Reporting on how the sport developed rom the 70s to modern day. The goal is to have your robotic 'mouse' solve a maze as fast as posible. These mice,aswell as the competitors that made them, have no prior knowledge of the course so the mice need to be able not only solve the maze quickly but also map out the the maze as efficiently as possible. There is an interseting caveate with this compition, because the shortest path will not always be the fastest, which can lead to different problems and solutions than traditional grid-based pathfinders.

\cite{candraDijkstrasAStarFinding2020} Candra et al compare A* and Dijkstra's Algorithm within the context of route mapping between petrol stations, They go into detail of how both algorithms work and compare the outcomes when running them in the same scenarios.

\cite{kimQuestPerfectPerfectmaze2015} kim et al, design a development tool to create the 'perfect' perfect maze. They have a quick comparrison comparison between Prim's algorithm \cite{zotero-item-159} and recursive backtracker, the former generating many short dead-ends` with the latter, having longer passages with little branching. kim discusses the flaw with them is that they are completely random as such not hard to design around exact needs for game designers. The solution they found was to create an evaluation function to asign generated mazes a score against user specified values - As such the program can then iterate through generated mazes until a desierd maze, or close enough, is made. They expand on the research with their future paper\cite{kimIntelligentMazeGeneration2018}

\begin{algorithm}
    \floatname{algorithm}{Algorithm}
    \caption{Binary Tree}\label{alg:BT}
    \begin{algorithmic}[1]
        \Procedure{BinaryTree}{$size$} \Comment{square grids so size is width \& height}
        \For{$i \gets 0, size$}
            \For{$j \gets 0, size$}
            \State $Position \gets (i,j)$
            \State $Dir \gets AvailiableDirs(Position)$
            \State $Index \gets Rand(0,len(DirsToMove))$
            \State $NextCell \gets DirsToMove[index]$
            \State  Connect(Pos, NextCell) \Comment{carve passege connecting the cells}
            \EndFor

            \EndFor
        \EndProcedure
        \Function{AvailiableDirs}{$pos$}\Comment{find the next cell to carve to}
            \State PossibleDirs[]
            \If{pos is within bounds SOUTH}\Comment Given SE Bias
                \State AddItem(PossibleDirs,SOUTH)
            \EndIf
            \If{pos is within bounds WEST}
                \State AddItem(PossibleDirs,EAST)
            \EndIf
            \State return PossibleDirs
        \EndFunction
    \end{algorithmic}
\end{algorithm}

\begin{algorithm}
    \floatname{algorithm}{Algorithm}
    \caption{Recursive backtracker}\label{alg:Rb}
    \begin{algorithmic}[1]
    \Procedure{RecursiveBacktracker}{curCell,size}
    
    \State $availDirs \gets getAvailDirs(curCell, size)$\Comment{returns random ordered list of dirs}
    \For{$dir,availDirs$}
        \State $NewCell \gets getCell(dir)$
    \If{$!NewCell.Visited$}
        \State $ConnectCells(NewCell)$
        \State $NewCell.Visited \gets TRUE$
        \State $RecursiveBacktracker(NewCell, size)$
    \EndIf
    \EndFor
    \EndProcedure
    \end{algorithmic}
\end{algorithm}

\begin{figure}
    \begin{center}

this is a recursive backtracker. The algorithm operates similarly to a depth first search: carving down a branch of a tree all the way till it ends, before looking at the other branches. It then backtracks to the first cell with unvisited neightbours and repeats until there are no unvisited cells. As figure \ref{fig:RB} shows, this results in little to no bias in the generation as appose to a binary tree, see figure \ref{fig:BT}.

    \caption{depthFirst}\label{alg:dp}
    \begin{algorithmic}[1]
    \Procedure{depthFirst}{Path,curCell,size,goal, solved}
    \State $PushBack(Path, curCell)$

    \For{$dir,availDirs$}
        \State $NewCell \gets getCell(dir)$

    \State $solved \gets TRUE$
    \State $return$
    \EndIf

        \State $NewCell.Visited \gets TRUE$
        \State $RecursiveBacktracker(NewCell, size)$
    \EndIf
    \EndFor
    \EndProcedure
        
    \end{algorithmic}
